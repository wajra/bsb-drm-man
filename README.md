# Code for Bandara et al. (2026)

This repository contains all the code, data, models, and figures for Bandara, Widenmann, and Pinsky (2026).

![alt text](https://github.com/wajra/bsb-drm-man/blob/main/drm_schema_banner.png)
**Figure 1 - Structure of the Dynamic Range Model for black sea bass in the Northeast US**

Dynamic range models (DRMs) are a class of process-based or mechanistic models 
that explicitly incorporate demographic processes (such as mortality, reproduction, 
and dispersal) to explain population dynamics and resulting species distribution shifts <sup>[1]</sup>.
Black sea bass (_Centropristis striata_) is a commercially important fish in the 
Northeast US<sup>[2]</sup>. Black sea bass in the Northeast US is treated as a 
single stock from Maine to Cape Hatteras and is managed by the Mid Atlantic 
Fisheries Council with NOAA Fisheries implementing rules and regulations. 
The current stock assessment (as of 2025) treats the stock as two subunits that 
are separated by the Hudson Canyon. Black sea bass has been expanding northwards 
into the Gulf of Maine over the past 20 years at a rapid rate <sup>[3]</sup> with 
this raising concerns about the it's impact on the fishery itself and how a sudden 
influx of black sea bass may potentially disrupt the Gulf of Maine ecosystem which 
supports lucrative fisheries such as the American Lobster. Previous research has 
found that black sea bass habitat can be explained by the physiological interaction 
between oxygen and sea temperature which makes it a versatile species in the face of climate change. 
Our goal with this dynamic range model is to test whether the use of models that attempt to 
directly infer relationships between environmental drivers and demographic processes better 
explain species biogeography. 


## Code structure

The code is structured in two main parts. One section is the R code that reads, cleans/filters, and prepares the Northeast US spring bottom trawl survey data for the dynamic range model (DRM).
The next section is for the Stan code that describe the dynamic range model itself.

### R

Contains the .R files that are to be run sequentially to set up the models, it's variations, and derive and show results.

### stan-src

Contains the .stan files that describe the model that fits observed abundance of our species of interest using several demographic processes linked with oceanic temperature.

### data

Contains all the data files required to run the code. This includes the Northeast Fisheries Science Center Bottom Trawl Survey data sourced from Ocean Adapt <sup>[4],[5]</sup>, it's resulting data after cleaning and processing, the 2021 black sea bass stock assessment data files (`.rdat` format), and shapefiles required to plot Figure 1 of the manuscript.

### processed-data

Contains all the data files that's generated by the analysis/prep code itself. Examples would be the black sea bass bottom trawl survey data for the spring season that's derived from the OceanAdapt raw data.

### figures

Contains all the major figures that's generated during the analysis.

### figures/supplementary-figures

Contains all the figures generated for model diagnostics and ended up in the supplementary section

### saved_models

Contains the models for the four candidate models in the manuscript.

### Installing RStan

I tried to get RStan working with R Version 3.6.1. However, I kept running into issues 
with the C++ compiler not being incompatible and even the simplest Stan code 
couldn't run without errors. What I would suggest is installing the latest version 
of R available (R version 4.0.0+). I successfully installed Stan on R version 4.1.2 ("Bird Hippie").  
I will list the steps below.

#### Step 1: Updating R (If you have an old version of R)

If you have a lot of R Packages, the best approach would be to save a list of the 
R Packages and then reinstall them to your new R version. R can be installed 
(for MacOS) from [this](https://cran.r-project.org/bin/macosx/) link.  
The code is shown below for saving a list of packages in old R and then reinstalling 
them with the new version of R.

```r
# In old version of R:
ip <- installed.packages()[,1]
write(ip,"rpackages_in_old_R.txt")
q()

# Install new version of R - https://cran.r-project.org/bin/macosx/

# In new version of R:
ip_new <- readLines("rpackages_in_old_R.txt")
setRepositories(graphics=FALSE, ind=1:6)
install.packages(ip_new)
```

#### Step 2: Install MacOS R toolchain package

These are developmental libraries required for Stan to work. They include the 
XCode command line tools and the GNU C/C++ libraries. You can download the package 
from [here](https://github.com/rmacoslib/r-macos-rtools/releases/tag/v4.0.0).  
More information on MacOS R toolchain package can be found [here](https://github.com/rmacoslib/r-macos-rtools)

#### Step 3: Install RStan and dependent libraries

First, uninstall any possible/previous existing version of RStan

```r
remove.packages("rstan")
if (file.exists(".RData")) file.remove(".RData")
```

Then install some prerequisites for R. These include C/C++ library handlers for R.

```r
install.packages(c("Rcpp", "RcppEigen", "RcppParallel", "StanHeaders"), type = "source")
```

Then install RStan

```r
install.packages("rstan", type = "source")
```

Then it's best to verify that RStan is working properly. If you can run the code 
below without any errors (RStan is Warning happy. So don't be too bothered with those) 
you should be set to do Bayesian hierarchical programming in R.

```r
example(stan_model, package = "rstan", run.dontrun = TRUE)
```

**Further instructions on working with RStan (including some examples) can be found at the 
[RStan Getting Started page](https://github.com/stan-dev/rstan/wiki/RStan-Getting-Started)**


## Understanding `Stan`

Stan is a probabilistic programming language that allows for Bayesian hierarchical programming with R. 
The syntax can be a little tough to get a hand on. It's best to refer the 
[Stan manual](https://mc-stan.org/docs/2_28/reference-manual/index.html) to get comfortable with it.
